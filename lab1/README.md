## 2. Прямий прохід

Мережа: X → Linear(4, 8) → ReLU → Linear(8, 3). Втрата — крос-ентропія, усереднена за об'єктами.

```
Z1 = X · W1 + b1                      (N×8)
A1 = max(Z1, 0)                       (N×8)
Z2 = A1 · W2 + b2                     (N×3)  — логіти

log_softmax(Z2)_ij = (Z2_ij − m_i) − log Σ_k exp(Z2_ik − m_i),   m_i = max_k Z2_ik
L = −(1/N) · Σ_i log_softmax(Z2)[i, y_i]
```

Зсув на максимум `m_i` забезпечує чисельну стабільність.

## 3. Збережені проміжні значення

Під час прямого проходу зберігаються `X`, `Z1`, `A1`, `Z2`. Кожне потрібне для зворотного проходу:

- `X` — для `dW1 = Xᵀ · dZ1`;
- `Z1` — для маски похідної ReLU `1[Z1 > 0]`;
- `A1` — для `dW2 = A1ᵀ · dZ2`;
- `Z2` — для `P = softmax(Z2)` і далі `dZ2`.

## 4. Зворотний прохід (формули) і розмірності

Y — one-hot матриця міток (N×3). Для крос-ентропії зі softmax:

```
P    = softmax(Z2)                    (N×3)
dZ2  = (P − Y) / N                    (N×3)

dW2  = A1ᵀ · dZ2                      (8×3)
db2  = Σ_i dZ2[i, :]                  (3,)

dA1  = dZ2 · W2ᵀ                      (N×8)
dZ1  = dA1 ⊙ 1[Z1 > 0]                (N×8)

dW1  = Xᵀ · dZ1                       (4×8)
db1  = Σ_i dZ1[i, :]                  (8,)
```

Звідки береться кожен градієнт:

- `dZ2 = (P − Y)/N`: похідна `−log p_y` за логітом `z_j` дорівнює `p_j − 1[j=y]`; множник `1/N` — від усереднення втрати за об'єктами.
- `dW2`, `db2`: Z2 = A1·W2 + b2 — афінний шар. Ваги отримують `A1ᵀ·dZ2`, зсув — суму `dZ2` за об'єктами (bias додається до кожного рядка).
- `dA1 = dZ2·W2ᵀ`: градієнт передається назад через ту ж матрицю ваг.
- `dZ1`: похідна ReLU дорівнює 1 при `Z1 > 0` і 0 інакше.
- `dW1`, `db1`: аналогічно до другого шару, з `X` замість `A1`.

### Розмірності (N = 105)

| Масив | Розмірність |

## 7. Дослід із навмисною помилкою

Команда: `uv run python main.py --bug`

### Прогноз

1. **Втрата** не зміниться: вона обчислюється у forward і від `backward` не залежить.
2. **Ненульові градієнти** зростуть рівно в `N = 105` разів, бо `dZ2` збільшується в `N` разів, а всі наступні градієнти лінійні за `dZ2`.
3. **Які перевірки виявлять помилку:** перевірка втрати з PyTorch пройде (втрата та сама), а порівняння градієнтів з PyTorch провалиться для всіх чотирьох. Чисельна перевірка також провалиться, бо чисельна похідна відповідає справжній втраті, яка містить `1/N`.

### Результат

| Перевірка | Без помилки | З помилкою |
|---|---|---|
| Втрата NumPy / PyTorch | пройдено | пройдено |
| Градієнт W1 з PyTorch | пройдено | не пройдено |
| Градієнт b1 з PyTorch | пройдено | не пройдено |
| Градієнт W2 з PyTorch | пройдено | не пройдено |
| Градієнт b2 з PyTorch | пройдено | не пройдено |
| Чисельна: W1[0,0] | пройдено | не пройдено |
| Чисельна: b1[0] | пройдено | не пройдено |
| Чисельна: W2[0,0] | пройдено | не пройдено |
| Чисельна: b2[0] | пройдено | не пройдено |

Відношення `backward() / чисельна похідна` для `b2[0]`: 8.979772708405 / 0.08552164498798 ≈ 105.

**Зіставлення з прогнозом:** збіглось. Помилку виявлено — це правильний результат досліду.

## 8. Висновки

- Ручний backprop збігається з PyTorch autograd з точністю 1.388e-16 та з чисельним диференціюванням з точністю 1.460e-10.
- Помилка множника `1/N` не видна за значенням втрати, але чітко виявляється порівнянням градієнтів з autograd і чисельною перевіркою. Тому перевіряти потрібно саме градієнти.
- Чисельна перевірка незалежна від autograd і може виявити помилки навіть тоді, коли еталон неточний або скопійований неправильно.
